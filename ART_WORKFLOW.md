# Art asset workflow

Правила для изображений, фонов, спрайтов и анимируемых персонажей в Erudition.

## Главное правило

Графика считается добавленной только когда она не просто лежит в репозитории, а реально импортируется Unity, назначена нужному объекту сцены/prefab и после повторной загрузки проекта ссылка остаётся валидной.

## Куда складывать

- Фоны экранов: `Assets/Art/Backgrounds/`.
- Одиночные персонажи/маскоты: `Assets/Art/`.
- Sprite Sheet: `Assets/Art/SpriteSheets/`.
- Не создавать снова `Assets/Art/Generated`.

## Как заменять уже подключённую картинку

Самый безопасный вариант — заменить PNG по тому же пути и НЕ менять его `.meta`.

Так сохраняется GUID, поэтому ссылки в сценах и prefab не превращаются в `Missing`.

Если нужен новый файл с новым именем:
1. добавить сам PNG;
2. добавить его `.meta`;
3. проверить GUID;
4. только после этого назначать его в scene/prefab;
5. после коммита заново скачать scene/prefab и проверить сериализованную ссылку.

## Настройки импорта UI-спрайта

Для обычного UI-спрайта:
- Texture Type: `Sprite (2D and UI)`;
- Sprite Mode: `Single`, если это один спрайт;
- Alpha Is Transparency: включено;
- Preserve Aspect на UI Image — по необходимости;
- не использовать физическую форму, если она не нужна;
- для прозрачных персонажей фон PNG должен быть реально прозрачным, а не белым/шахматным.

Для Sprite Sheet:
- Sprite Mode: `Multiple`;
- каждый кадр имеет стабильное имя;
- одинаковый размер кадра и одинаковый pivot для всех состояний;
- после slicing проверить `nameFileIdTable` в `.meta`.

## Фоны

Основной размер reference UI: `1080 × 2340`.

Фон и персонаж не должны быть одной картинкой, если персонаж должен двигаться или анимироваться.

Фон хранится отдельно. Сова, декоративные части и другие анимируемые элементы — отдельными прозрачными спрайтами.

## Анимация персонажа

Для простых idle-анимаций:
- сам объект совы должен существовать в scene/prefab;
- runtime-код только меняет состояние/scale/sprite;
- объект не создаётся целиком программно;
- лёгкое дыхание и редкое моргание предпочтительнее постоянного движения.

Если моргание делается кадрами:
- `open` и `closed` должны иметь один размер canvas;
- сова не должна прыгать по позиции между кадрами;
- pivot должен совпадать;
- лучше менять только sprite, не перестраивать layout.

## Проверка после любого изменения графики

Проверить:
- файл существует в GitHub;
- `.meta` существует;
- GUID картинки совпадает со ссылкой в scene/prefab;
- `m_Father`/prefab parent корректен;
- нужный объект входит в `m_Children` родителя;
- `m_Sprite` или `m_Texture` не равен Missing/нулю без причины;
- prefab instance ссылается на настоящий GUID prefab;
- после коммита повторно скачать изменённые YAML/meta и проверить реальные ссылки.

Не считать задачу завершённой только потому, что PNG был загружен в репозиторий.
